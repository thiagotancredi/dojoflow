# Mensalidades Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cobranças automáticas (taxa de matrícula + mensalidades), baixa manual com abatimento do mais antigo, lançar meses anteriores, página de cobrança com WhatsApp e Configurações → Cobrança.

**Architecture:** Regras puras em `services/billing_rules.py` (datas, situação, abatimento) testadas isoladas; `services/billing.py` (`BillingService`) dono das cobranças, baixas e geração idempotente; rotas REST novas em `api/routes/billing.py`. O site consome pelo cliente tipado (`schema.d.ts` regenerado). Situação "atrasada" é calculada, nunca gravada.

**Tech Stack:** FastAPI + SQLAlchemy async + Alembic + pytest (Postgres); React 19 + React Router 7 + React Hook Form/Zod + shadcn/Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-10-21-billing-design.md`

## Global Constraints

- Toda regra nos services do backend; site e bot chamam o mesmo código.
- Dinheiro `Decimal` com 2 casas; datas sem fuso, "hoje" = `local_today()` de `services/belt_rules.py`.
- Multi-tenant: tudo filtrado pelo `academy_id` do token; a API expõe só `public_id` (UUID).
- Erros de regra: `ConflictError`/`NotFoundError` com `code` em MAIÚSCULAS; o site traduz em `frontend/src/lib/api/errors.ts`.
- Situações da API: `paid` | `partial` | `overdue` | `upcoming` | `waived` (`overdue` = vencimento < hoje e não `paid`/`waived`).
- Frontend: tema grafite + petróleo, só tokens de `theme.css`, claro e escuro; nada depreciado; `tsc` + ESLint verdes; nunca `cat >` em arquivos do frontend com o Vite rodando.
- Tipos do frontend: regenerar com `openapi-typescript http://localhost:8000/openapi.json` para arquivo temporário + `mv` para `src/lib/api/schema.d.ts`.
- Backend: rodar só o teste da tarefa; suíte completa uma vez na última tarefa. Sem testes automáticos de frontend (decisão da V1).
- Telegram: nada de mensalidade no bot; só a matrícula (valor obrigatório + taxa).

## Review Focus

1. **Baixa que não bate:** soma das alocações de uma baixa = valor da baixa; excluir a baixa devolve cada cobrança exatamente ao saldo anterior. → Tarefa 5, `test_delete_payment_restores_previous_balances`.
2. **Cobrança duplicada:** chamar a geração duas vezes (ou o disparo diário + a geração sob demanda ao mesmo tempo) não cria duas mensalidades do mesmo mês. → Tarefa 3, `test_generation_is_idempotent`.
3. **Mensalidade nascendo atrasada:** matrícula nova e alunos antigos na ligação do recurso nunca recebem mensalidade automática com vencimento no passado. → Tarefa 1 (backfill) e Tarefa 3, `test_first_monthly_charge_is_next_month`.
4. **WhatsApp para quem não deve:** aluno sem atraso não recebe `whatsapp_url`; menor de 18 com responsável com telefone recebe o link do responsável. → Tarefa 8, `test_whatsapp_url_only_for_overdue` e `test_whatsapp_goes_to_responsible_for_minor`.
5. **Baixa maior que a dívida / sem dívida:** recusada com o máximo no erro. → Tarefa 5, `test_payment_above_open_total_is_rejected`.
